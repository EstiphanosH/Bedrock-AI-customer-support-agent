# Customer Support AI Agent — Project Reflection

Building the Customer Support AI Agent helped me understand how to combine managed AI services and tools into a practical support workflow. I integrated the Amazon Bedrock AgentCore Runtime with an MCP Gateway, a Bedrock Knowledge Base, AgentCore Memory, Code Interpreter, and browser access. Each component serves a distinct purpose: Gateway tools connect the agent to support operations, retrieval grounds product and policy answers in source content, memory supports continuity across sessions, and specialized tools handle calculations and web navigation.

One important design choice was to use Knowledge Base retrieval for loyalty-tier and policy questions instead of relying on the model’s general knowledge. During testing, the Platinum-tier answer needed to reflect the retrieved benefits—free same-day shipping, a 15% discount, and priority customer support—without adding unrelated information. I refined the system instructions to require retrieval and keep answers focused on the question. This reinforced the importance of grounding responses in authoritative data and evaluating not only whether an answer sounds plausible, but whether it matches the available evidence.

A key troubleshooting lesson was that working code does not guarantee working cloud permissions. The memory hook was implemented to retrieve customer context and save interactions, but runtime logs exposed permission failures for memory operations. This showed me why logs and end-to-end tests are essential: a feature can be present in the code while failing at runtime. I also deployed a corrected Lambda package for order tracking after discovering that the deployed function returned a placeholder response rather than the expected order details.

For production, I would strengthen security and reliability before handling real customer data. The project configuration uses a temporary Gateway `NONE` authorizer, which should not be exposed to sensitive information or production traffic. I would replace it with appropriate authentication and least-privilege permissions, add monitoring and alerts for tool and memory failures, validate tool outputs against schemas, and test fallback behavior. For example, if Code Interpreter becomes unavailable, the current tier-only fallback cannot report points redeemed or remaining points; production logic should explicitly handle that limitation rather than imply a complete calculation.

Overall, the project improved my understanding of tool orchestration, retrieval-grounded responses, cloud IAM troubleshooting, and the difference between implementation and verified behavior.
